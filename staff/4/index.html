바이브 코딩 입문

코드를 몰라도, 원하는 것을 말로 설명하면 AI가 프로그램을 만들어 줍니다.
이번 호에서는 직접 하나 만들어 보고, 그 뒤에서 어떤 일이 일어나는지 살펴봅니다.

CONNECT

이번엔 질문이 아니라
'프로그램'을 부탁합니다

3호에서는 AI에게 좋은 질문을 설계받는 법을 살펴봤습니다.

이번에는 그 요청으로 글이나 이미지가 아니라, 직접 눌러 보고 쓸 수 있는 프로그램을 받아 봅니다.

좋은 요청이 좋은 결과를 만든다는 원리는 그대로입니다. 달라지는 건 결과물이 '읽는 것'에서 '쓰는 것'으로 바뀐다는 점입니다.

DEFINE

바이브 코딩이
뭔가요?

바이브 코딩이란 코드를 직접 쓰지 않고, 원하는 것을 말로 설명하며 AI와 함께 프로그램을 만들어 가는 방식입니다.

3호에서 건축가에게 설계도를 부탁했다면, 이번에는 시공까지 맡기는 셈입니다. 완성된 집을 둘러보고 "부엌을 조금 넓혀 주세요"라고 말하면 되고, 벽돌은 직접 쌓지 않아도 됩니다.

  • 개발을 배우지 않아도 시작할 수 있습니다
  • 한 번에 완성하지 않고, 대화하며 고쳐 갑니다
  • 수업에 꼭 맞는 작은 도구를 직접 만들 수 있습니다
TRY IT

일단, 하나 만들어 볼까요?

설명은 나중에 하고, 먼저 해 봅니다. 아래 요청을 ChatGPT에 그대로 붙여넣어 보세요.

요청문

다음 기능을 가진 간단한 일정관리 앱을 HTML로 만들어 주세요.
- 캘린더를 열어 날짜를 선택하고, 선택한 날짜마다 [할 일 등록]을 통하여 To-do list를 등록할 수 있다.
- 또한 [일정 등록]을 통해 시간이 정해진 일정을 등록할 수 있다.

요청을 보내자 HTML 파일이 만들어졌습니다.
1

ChatGPT에 요청문을 붙여넣고 보냅니다

2

완성되면 나오는 [다운로드] 링크로 HTML 파일을 저장합니다

3

저장한 파일을 더블클릭하면 브라우저에서 열립니다

4

날짜를 눌러 할 일과 일정을 등록해 보세요

ChatGPT 화면 기준: 2026년 10월 14일. 화면 구성은 자주 바뀔 수 있어요.

RESULT

요청하지 않은 기능까지
들어 있었어요

완성된 일정관리 앱. 요청문 몇 줄이 이 화면이 되었습니다.
요청한 것날짜 선택 · 할 일 등록 · 시간 일정 등록

AI가 알아서 더한 것

  • 등록한 항목의 수정·삭제
  • 할 일 완료 체크
  • 새로고침해도 남아 있는 자동 저장
  • [오늘] 버튼, 항목이 있는 날짜에 표시되는 점
  • 종료 시간이 시작보다 빠르면 알려 주는 안내
  • 휴대폰 화면에 맞춰 바뀌는 배치

바이브 코딩의 편리함이자 주의할 점입니다. AI는 "있으면 좋을 것"을 알아서 채웁니다. 그래서 결과를 꼭 눌러 보고, 원하던 것과 맞는지 확인해야 합니다.

INSIDE

방금 만든 것의 정체,
프론트엔드

방금 받은 파일 하나는 세 가지 언어로 이루어져 있습니다. 화면의 보라색 [+ 할 일 등록] 버튼이 세 언어에서 각각 어떻게 쓰였는지 볼까요?

HTML뼈대와 내용
<button class="primary" id="addTodo">+ 할 일 등록</button>

여기에 '+ 할 일 등록'이라는 버튼이 있다.

CSS겉모습
button.primary{background:#4f46e5;color:white}

이 버튼은 보라색 바탕에 흰 글씨로 보여 줘라.

JavaScript동작
$('addTodo').addEventListener('click',()=>openEditor('todo'))

이 버튼을 누르면 할 일 입력창을 열어라.

이 셋을 묶어 프론트엔드(화면 쪽)라고 부릅니다. 브라우저가 이 코드를 읽어서 우리가 보는 화면을 그립니다.

식당으로 치면 HTML은 건물 구조와 메뉴판, CSS는 인테리어, JavaScript는 주문을 받고 움직이는 직원입니다. 손님이 보는 홀 전체가 프론트엔드입니다.

코드를 읽을 필요는 없어요. 궁금하다면 저장한 HTML 파일을 우클릭해 메모장 같은 텍스트 편집기로 열면 이 코드가 보입니다.

BACKEND

그런데, 이 앱에는
한계가 있어요

방금 만든 앱의 일정은 지금 쓰는 이 브라우저 안에만 저장됩니다. 다른 컴퓨터나 휴대폰에서 열면 비어 있고, 브라우저 데이터를 지우면 함께 사라집니다.

이런 한계를 넘고 싶을 때 필요한 것이 백엔드(서버 쪽)입니다.

손님이 보는 홀이 프론트엔드라면, 주문을 받아 요리하고 재료를 보관하는 주방과 창고가 백엔드입니다.

이런 기능을 원할 때 백엔드가 필요해요

여러 기기에서같은 일정을 보고 싶다 → 서버 + 데이터베이스
로그인내 일정만 보고 싶다 → 서버 + 데이터베이스
함께 쓰기여러 사람이 같은 자료를 보고 싶다 → 서버 + 데이터베이스
외부 서비스AI·날씨 같은 서비스를 쓰고 싶다 → 서버 + API
프론트만으로 충분혼자 쓰는 타이머, 계산기, 퀴즈처럼 저장·공유가 필요 없는 도구. ChatGPT가 한 번에 만들어 주는 규모의 앱은 보통 여기에 해당합니다.

3호의 [프롬프트 만들기] 도구도 백엔드를 쓴 예입니다. 버튼(프론트엔드)을 누르면 서버가 AI에게 대신 요청을 보내고 결과를 돌려줍니다. AI 서비스를 쓰는 열쇠(API 키)를 화면 코드에 넣으면 누구나 볼 수 있어서, 서버가 대신 보관하는 구조가 흔합니다.

BASIC

주소를 입력하면
무슨 일이 일어날까요?

웹앱을 다른 사람이 쓰게 하려면 인터넷의 기본 구조를 알아 두면 좋습니다.

1

주소를 입력해요. 브라우저 주소창에 사이트의 이름, 즉 도메인을 입력합니다.

2

DNS가 번호로 바꿔요. 도메인은 사람이 읽기 쉬운 이름이고, 컴퓨터는 숫자로 된 주소(IP)로 찾아갑니다. DNS는 이름을 번호로 바꿔 주는 주소록입니다.

도메인example.com
▼ DNS가 찾아 줘요
IP203.0.113.10

example.com과 숫자는 설명을 위한 예시예요.

3

서버가 응답해요. 요청을 보낸 쪽과 받는 쪽은 이렇게 구분합니다.

클라이언트요청하는 쪽. 주소를 입력한 내 브라우저(손님)
서버요청을 받아 응답하는 쪽. 파일을 보내 주는 컴퓨터(주방)

이 서버 컴퓨터에 파일을 올려 두고 늘 켜 두는 공간을 호스팅이라고 합니다.

4

브라우저가 화면을 그려요. 받은 HTML·CSS·JavaScript를 읽어 화면으로 보여 줍니다.

식당으로 치면 도메인은 가게 이름, IP는 실제 번지수, DNS는 지도 앱의 검색 기능입니다. 손님(클라이언트)이 주문하면 주방(서버)이 응답하고, 호스팅은 그 주방이 들어선 건물과 부지입니다.

HOW

처음엔 이렇게
시작하세요

1

작게 시작하세요. "학교 관리 시스템"이 아니라 "타이머 하나"처럼 기능 하나로 시작합니다.

2

한 번에 하나씩 고치세요. 결과를 보고 "이 부분만 이렇게 바꿔 줘"라고 말합니다.

3

직접 눌러 보며 확인하세요. 코드를 못 읽어도, 입력하고 눌러 보면 제대로 되는지 알 수 있습니다.

4

오류는 그대로 알려 주세요. 안 될 때는 화면의 오류 메시지를 복사해 AI에게 붙여넣으면 됩니다.

학생 개인정보나 성적 같은 자료는 입력하지 않습니다. API 키와 비밀번호는 다른 사람에게 보이지 않게 하세요.
